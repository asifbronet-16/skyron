# Deploying to CWP

The site is a static export served by Apache on CWP. The two forms are the only
server-side code: small PHP handlers that send email through Microsoft Graph
from the Microsoft 365 mailbox, as the old Node server did.

| Path in the upload | What it is |
| --- | --- |
| `*.html`, `_next/`, `assets/`… | The site, built by `next build` |
| `.htaccess` | HTTPS, `www` → `skyron.me`, clean URLs (`/contact` serves `contact.html`), the old WordPress redirects, caching. Generated by `scripts/cwp-release.mts` |
| `api/contact.php`, `api/careers.php` | Form handlers (source in `public/api/`) |
| `api/_lib/` | Their shared code and `site.json`. Apache answers 403 for this folder |
| `api/.user.ini` | PHP upload limits for the CV (4 MB) |

The Microsoft secret is **not** in the upload. It lives in `skyron-mail.php`,
one folder above the web root, so Apache can never serve it.

## Build

```bash
npm ci            # first time only
npm run package   # → dist/skytron.zip
```

Needs Node 22.18 or later. The script refuses to produce a zip with backslash
paths or missing files.

Under `npm run dev` the forms show their "something went wrong" message,
because there's no PHP. To try them, deploy to CWP (below).

## One-time setup on CWP

1. **Domain:** add `skyron.me` (with `www`) to the CWP account and note its
   web root, e.g. `/home/<user>/public_html`.
2. **PHP:** PHP 7.4 or later, served through PHP-FPM (needed for
   `api/.user.ini`), with the `curl` extension. That's CWP's default.
3. **Mail settings:** copy `deploy/skyron-mail.example.php` to
   `/home/<user>/skyron-mail.php`, one folder above the web root, never inside
   it. Fill in the four Microsoft values from the old server's `.env.local`.
   - While testing, put **your own address** in `contact_inbox` and
     `careers_inbox`, so test submissions don't reach the client.
   - Make the account user the owner and set permissions to `600`. The handlers look for the file
     up to three folders above the web root, or at `$SKYRON_MAIL_CONFIG`.
4. **SSL:** issue Let's Encrypt for `skyron.me` and `www.skyron.me` once DNS
   points at the server (see go-live).

## Each release

1. `npm run package`.
2. In CWP's File Manager, open the web root and delete the old site files.
   `skyron-mail.php` is outside it, so it isn't affected.
3. Upload `dist/skytron.zip` into the web root, extract it there, and delete
   the zip.
4. Run the checks below.

## Checks

Before DNS points here, add `<server IP> skyron.me www.skyron.me` to your
computer's hosts file to test the new server. The certificate warning is
expected until SSL is issued.

- [ ] `/`, `/contact`, `/careers` and `/creative-solutions/3d-content-creation` load.
- [ ] `http://` redirects to `https://`, `www.skyron.me` redirects to `skyron.me`, and `/contact/` redirects to `/contact`.
- [ ] Old URLs redirect: `/3d-content-creation` → `/creative-solutions/3d-content-creation`, `/2024/05/01/anything` → `/blogs`.
- [ ] `/api/contact.php` opened in the browser shows `{"status":"error","message":"This address only accepts form submissions."}`.
  **If you see PHP code instead, PHP isn't enabled for the domain. Stop and fix that first.**
- [ ] `/api/_lib/site.json` and `/api/.user.ini` return 403.
- [ ] Send the contact form. The email arrives at your test inbox, and replying goes to the address typed in the form.
- [ ] Send the careers form with a PDF of about 2.4 MB. The email arrives with the CV attached.
  If it says the CV is too large, `api/.user.ini` hasn't taken effect yet; PHP reloads it within 5 minutes.

## Go-live

1. Point DNS for `skyron.me` and `www` at the server, then issue SSL.
2. In `skyron-mail.php`, empty `contact_inbox` and `careers_inbox`. Mail then
   goes to `hello@skyron.me` and `career@skyron.me`.
3. Send one real test enquiry, and tell the client to expect it.
4. Once DNS has propagated, stop the old server's PM2 app and remove its
   `.env.local`, since it holds the same secret.

## When a form says "We couldn't send…"

The handlers log to the domain's PHP error log. Their lines start with `[mail]`,
`[careers]` or `[form]`.

| Log says | Fix |
| --- | --- |
| `skyron-mail.php not found or incomplete` | Check the file is above the web root, readable by the account user, and has all four Microsoft values |
| `AADSTS7000222` | The client secret has expired. Create a new one in Entra ID (App registrations → Certificates & secrets) and update `client_secret` |
| `Microsoft Graph responded 403` | The app isn't allowed to send as `sender`. Check the Exchange Online "Application Mail.Send" scope for that mailbox |
| `PHP curl extension is not installed` | Enable `curl` for the domain's PHP version in CWP |

Note when the client secret expires: the forms stop sending on that date.
